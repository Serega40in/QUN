# S40in AI Income

Личная панель для управления заказами S40in AI Studio, учёта реальных поступлений и накопления фонда на оплату AI-инструментов.

## Публикация

Проект размещён как самостоятельное приложение в каталоге income репозитория Serega40in/QUN:

https://serega40in.github.io/QUN/income/

## Авторизация

Вход выполняется через QUN ID: браузер отправляет логин и пароль в существующую Supabase Edge Function qun-auth с действием login. Функция возвращает Supabase session; приложение устанавливает её через supabase-js. Отдельный пароль или аккаунт для панели не создаётся.

Публичный publishable key предназначен для клиентского приложения. Секретный service-role key, пароли и приватные токены в репозитории отсутствуют.

## Данные и безопасность

Данные хранятся в отдельной группе таблиц ai_income_* в существующем проекте Supabase QUN:
- ai_income_settings — цель накопления;
- ai_income_orders — клиенты и заказы;
- ai_income_transactions — поступления, расходы и резерв;
- ai_income_tasks — план действий.

На каждой таблице включена Row Level Security. Политики разрешают пользователю работать только со строками, где user_id совпадает с auth.uid(). Доступ anon к этим таблицам отозван; права CRUD выданы authenticated.

## Функции MVP

- обзор заказов, поступлений, задач и прогресса фонда;
- добавление и изменение статусов заказов;
- учёт доходов, расходов и перевода в резерв;
- план действий с приоритетами и сроками;
- изменение суммы финансовой цели;
- экспорт журнала операций в CSV;
- адаптивный интерфейс для телефона и компьютера.

## Финансовая логика

Суммы разных валют не складываются в один итог. В резерв подписки записываются только операции в USD. Это учётная запись, а не фактический перевод в криптокошелёк. Перевод средств и оплата подписки выполняются владельцем отдельно.

Цель по умолчанию — 25 USD, рабочий ориентир для оплаты ChatGPT Plus и небольшого запаса на комиссии. Перед оплатой нужно сверить фактическую цену и доступный способ оплаты в аккаунте.

## Разработка

Приложение — статический HTML/CSS/JS без сборщика. Клиент Supabase загружается как ES module через esm.sh. Для локального тестирования достаточно любого локального HTTP-сервера, например Python http.server или VS Code Live Server.

Перед выпуском проверь вход через QUN ID, создание тестового заказа, операции и задачи. Не используй реальные клиентские данные для тестов.

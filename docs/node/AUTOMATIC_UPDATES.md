# Автоматические обновления QUN Node

## Что уже добавлено

- Windows-клиент проверяет обновления при запуске и далее каждые 6 часов. Новая версия скачивается в фоне; после проверки показывается предложение перезапустить приложение. Установщик NSIS сохраняет каталог данных узла.
- Android-клиент проверяет версии QUN Node при запуске и позволяет скачать APK, проверить SHA-256 из GitHub Releases и передать APK системному установщику. Android требует подтверждения установки.
- Релизы Windows и Android публикуются единым GitHub Actions workflow по тегу `qun-node-vX.Y.Z`.

## Одноразовая настройка секретов репозитория

Откройте GitHub → `Serega40in/QUN` → **Settings → Secrets and variables → Actions → New repository secret**. Не помещайте приватные ключи в исходный код.

### 1. Подпись метаданных обновления Windows

В каталоге `services/qun-node/desktop` выполните команду `npx electron-builder create-update-key` и следуйте подсказкам. Сохраните закрытый Ed25519 PEM-ключ в менеджере паролей и добавьте его содержимое как секрет:

- `QUN_UPDATE_SIGN_PRIVATE_KEY` — закрытый PEM-ключ. Никогда не публикуйте его и не коммитьте в Git.

Подписанный манифест позволяет клиенту проверить, что список файлов обновления опубликован владельцем ключа. Проверка подписи Windows EXE сертификатом издателя отдельно не настроена: для устранения предупреждения SmartScreen позднее понадобится сертификат подписи кода.

### 2. Постоянная подпись Android APK

Создайте release keystore один раз на своём компьютере. Храните его в резервной копии вне GitHub:

```bash
keytool -genkeypair -v -keystore qun-node-release.jks -alias qun-node -keyalg RSA -keysize 2048 -validity 10000
```

Добавьте секреты:

- `QUN_ANDROID_KEYSTORE_BASE64` — содержимое файла keystore, закодированное в Base64;
- `QUN_ANDROID_KEYSTORE_PASSWORD` — пароль keystore;
- `QUN_ANDROID_KEY_ALIAS` — обычно `qun-node`;
- `QUN_ANDROID_KEY_PASSWORD` — пароль ключа.

PowerShell для Base64:

```powershell
[Convert]::ToBase64String([IO.File]::ReadAllBytes(".\\qun-node-release.jks"))
```

Ключ нельзя менять после публикации первой стабильной версии: Android не примет обновление, подписанное другим сертификатом. Если keystore потерять, для прямого APK-обновления придётся публиковать приложение с другим идентификатором или проходить отдельную миграцию.

## Выпуск новой версии

1. Увеличьте версию в `services/qun-node/desktop/package.json` и `node-android/build.gradle.kts` (`versionName` должен совпадать, `versionCode` Android только растёт).
2. Создайте и отправьте тег, совпадающий с версией, например `qun-node-v0.3.0`.
3. Workflow **Release QUN Node with automatic updates** соберёт Windows NSIS/portable и Android APK, а затем опубликует assets в GitHub Release.
4. Клиент Windows получит обновление из Release. Android-клиент найдёт релиз с тегом `qun-node-v` и скачает APK с проверкой SHA-256.

## Важное про уже установленные тестовые версии

Старые Windows-клиенты без updater-модуля нужно один раз обновить установщиком вручную. После установки updater-enabled версии последующие обновления будут загружаться автоматически.

Предыдущие Android APK собирались как debug APK на временных GitHub runners, поэтому у них может быть другой debug-сертификат. Перед переходом на постоянную release-подпись может понадобиться удалить старый тестовый APK и установить первый стабильный APK заново. Удаление Android-приложения удалит локальный токен регистрации узла, поэтому после переустановки потребуется повторная регистрация.

Для Android полностью тихая установка недоступна обычному APK-клиенту: приложение скачивает и проверяет пакет, а окончательное подтверждение делает системный установщик. Если QUN Node будет опубликован в RuStore, можно интегрировать RuStore In-app Updates SDK и использовать обновление внутри магазина.

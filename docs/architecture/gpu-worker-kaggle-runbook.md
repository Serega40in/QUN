# QUN GPU Worker — Kaggle acceptance runbook
Дата: 2026-11-13
Статус: операционный чек-лист для следующего запуска после успешного pre-flight. Секреты и реальные токены в этот документ не помещать.

## Что уже подтверждено в рабочей сессии
- Kaggle runtime получил GPU T4 и CUDA доступна.
- Репозиторий QUN клонирован в рабочую среду.
- ComfyUI исходники присутствуют.
- Реестр/регистрация узла доступны.
- DreamShaper 8 checkpoint скачан в `/kaggle/working/ComfyUI/models/checkpoints/dreamshaper_8.safetensors` (около 1.99 GB).
- Pre-flight показал: QUN repo, ComfyUI, registry file, Supabase publishable key, node ID и node token присутствуют.
- Предыдущая ошибка была связана с тем, что backend не видел добавленный ключ; не считать исправленным, пока реальный сетевой запрос и heartbeat не подтверждены.
- В предыдущей сессии ноутбук был перегружен экспериментальными ячейками; этот runbook предлагает компактный порядок, но не утверждает, что старые ячейки уже удалены.

## Цель одного теста
Провести один безопасный тестовый job от создания до результата:
**scheduler/API → очередь → Kaggle worker → ComfyUI → файл результата → публикация результата/статуса → подтверждение в API**.

Не скачивать checkpoint повторно, если файл существует и его размер/контрольная сумма проходят проверку.

## Перед стартом
- [ ] Runtime Kaggle активен и GPU accelerator включён.
- [ ] Интернет/доступ к нужным endpoint проверен.
- [ ] Repo commit/branch зафиксированы в выводе.
- [ ] ComfyUI запускается и отвечает на локальный health check.
- [ ] Модель существует, размер не нулевой; при наличии опубликованной checksum сверить её.
- [ ] У worker настроены только необходимые переменные окружения.
- [ ] Используется publishable/anon key там, где это предусмотрено RLS; service-role key не помещать в notebook, output, GitHub или клиентский код.
- [ ] Node token не печатать целиком. Выводить только PRESENT/MISSING и, если нужно, последние 4 символа локально.
- [ ] Выбран один операторский workflow из allow-list. Не принимать произвольный путь или произвольный workflow JSON из payload задания.

## Порядок проверки
### A. Pre-flight
Вывести только безопасную диагностику:
- Python version, torch version, CUDA available, GPU name;
- repository path + commit SHA;
- ComfyUI path + process/health;
- checkpoint path + file size;
- наличие требуемых env vars как boolean;
- node ID (не секрет) и наличие node token без раскрытия значения.

### B. ComfyUI отдельно от очереди
1. Запустить ComfyUI.
2. Проверить локальный health endpoint.
3. Отправить небольшой операторский workflow с низким разрешением/числом шагов.
4. Убедиться, что history сообщает завершение и output-файл действительно существует.
5. Проверить тип, размер и время файла. Не считать пустой history успешной генерацией.

### C. Worker ↔ backend
1. Запустить один экземпляр worker.
2. Подтвердить heartbeat/registration по ответу backend; не считать локальное наличие токена доказательством успешной авторизации.
3. Проверить получение одного безопасного тестового job.
4. Зафиксировать job ID, тип задания и итоговый статус без токенов/персональных данных.
5. Убедиться, что output выбран из фактической history записи ComfyUI, а не из случайного старого файла в output directory.
6. Подтвердить, что backend сохраняет результат/метаданные и scheduler видит terminal status.
7. Проверить повторный запуск: один и тот же job не должен случайно оплачиваться/обрабатываться дважды; retry должен быть идемпотентным.

### D. Если backend не видит ключ
Проверять по порядку, не меняя несколько факторов сразу:
1. Точное имя переменной окружения, ожидаемое кодом.
2. Значение загружено до импорта модулей/создания клиента.
3. Нет пустого значения, лишних кавычек или пробелов.
4. URL проекта соответствует тому же Supabase project, где находится нужная функция/таблица.
5. Функция действительно читает эту переменную и не ожидает другой ключ.
6. RLS / права / JWT-проверка: HTTP 401 и 403 — разные классы ошибки.
7. Проверить статус-код и безопасное тело ответа, удалив из логов заголовки Authorization, токены и пользовательские данные.
8. Перезапустить клиент/worker после изменения env. Не публиковать ключи в выводах ноутбука.

### E. Финальный acceptance report
Тест успешен только если все пункты подтверждены:
- [ ] CUDA/GPU доступна.
- [ ] ComfyUI health OK.
- [ ] Workflow завершён.
- [ ] Новый output-файл создан именно этим job.
- [ ] Worker heartbeat принят backend.
- [ ] Job перешёл в terminal success.
- [ ] Backend получил корректные metadata/result reference.
- [ ] Повторный запрос не создаёт дубль.
- [ ] Логи очищены от секретов.
- [ ] Kaggle output содержит только нужные артефакты.

## Минимальный набор ячеек в чистом notebook
1. **Config** — пути, имена env vars, безопасные настройки; секреты не hardcode.
2. **Pre-flight** — диагностика GPU/repo/ComfyUI/model/env.
3. **Start ComfyUI** — запуск процесса и health wait.
4. **Smoke test** — один малый workflow.
5. **Start QUN worker** — единственная рабочая точка входа worker.
6. **Observe one job** — статус, job ID, output metadata; не печатать credentials.
7. **Stop/cleanup** — аккуратно остановить процессы и очистить временные файлы, сохранив нужные outputs.

Удалять старые ячейки можно только после сохранения текущего notebook как backup или создания новой чистой копии. Не удалять исходный notebook до подтверждения успешного end-to-end теста.

## Следующий технический приоритет
1. Исправить и проверить backend authentication/heartbeat.
2. Закрепить один рабочий путь запуска worker и записать его в notebook.
3. Добавить тест на stale job, retry и timeout.
4. Только затем добавлять второй worker и распределение по возможностям.
5. Затем реализовать отчёт о capability: GPU model, VRAM, supported workflows, model cache, queue latency и success rate.

## Security rules
- Никогда не коммитить `.env`, `credentials.json`, node token, Supabase service-role key или Telegram bot token.
- Если секрет случайно попал в публичный вывод/коммит — отозвать и заменить его; простого удаления строки недостаточно.
- Worker не должен выполнять произвольные shell-команды из job payload.
- Не подключать пользовательские/private files к volunteer nodes до шифрования и отдельной модели доступа.
- Не заявлять о запуске распределённой сети по факту одного Kaggle worker: это одиночный пилотный узел до подтверждения нескольких независимых операторов.

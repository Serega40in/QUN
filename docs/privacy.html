QUN Messenger · Как мы обрабатываем данные пользователей

Дата редакции: 11 октября 2026 года.

Настоящая Политика описывает обработку персональных данных при использовании QUN Messenger — сервиса учётных записей пользователей и личных сообщений.

Используя QUN Messenger, пользователь может передавать сведения, необходимые для регистрации, входа и обмена сообщениями. Оператор обрабатывает их только для целей, описанных в этой Политике, и в соответствии с применимым законодательством Российской Федерации. До публичного запуска оператору необходимо сверить документ с фактической конфигурацией приложения, базой данных и настройками инфраструктуры.

1. Какие данные могут обрабатываться

  • Данные учётной записи: имя пользователя (username), отображаемое имя и сведения профиля, которые пользователь добавляет самостоятельно.
  • Данные для входа: пароль в рамках механизма аутентификации. Пароль не должен храниться в открытом виде; аутентификация выполняется средствами подключённого сервиса авторизации.
  • Телефон: только если пользователь привязывает номер к учётной записи или вводит его для входа; наличие номера само по себе не означает подтверждение владения им.
  • Сообщения: текст и другие данные, которые пользователь отправляет в личных диалогах, а также технические идентификаторы, необходимые для доставки сообщений и работы списка диалогов.
  • Технические данные: минимальные сведения, необходимые для обеспечения безопасности, диагностики ошибок и работы приложения, если они фактически собираются используемой инфраструктурой.

2. Для чего используются данные

Данные используются для создания и защиты учётной записи, входа в сервис, отображения профилей, поиска пользователей, доставки сообщений, синхронизации диалогов, обеспечения безопасности и устранения технических неисправностей.

Данные не должны использоваться для рекламы или передаваться для рекламного профилирования без отдельного законного основания и соответствующего информирования пользователей.

3. Хранение и обработка

QUN использует серверную инфраструктуру Supabase для аутентификации и хранения данных приложения. Фактический регион размещения проекта, применимые условия поставщика и возможные трансграничные передачи должны быть проверены оператором по настройкам проекта и документам поставщика.

Доступ к профилям, диалогам и сообщениям должен ограничиваться правилами безопасности базы данных и предоставляться только в объёме, необходимом для работы сервиса. Не публикуйте в открытом коде секретные ключи, пароли или закрытые токены.

4. Передача третьим лицам

Данные могут обрабатываться поставщиками инфраструктуры, необходимыми для работы сервиса, в пределах их технической роли и применимых условий. Оператор должен учитывать требования законодательства Российской Федерации к поручению обработки персональных данных, локализации и трансграничной передаче, если они применимы к фактической схеме работы сервиса.

QUN не должен продавать персональные данные пользователей.

5. Сроки хранения и удаление

Данные хранятся столько, сколько необходимо для работы учётной записи и выполнения указанных целей, либо в течение иного срока, требуемого применимым законодательством. После прекращения необходимости данные удаляются или обезличиваются, если их сохранение не требуется по закону.

Для запроса доступа, исправления или удаления данных напишите на serega40-in@yandex.ru. В обращении укажите имя пользователя и суть запроса; не отправляйте пароль. Оператор проверит, что запрос исходит от владельца аккаунта, и ответит в сроки, предусмотренные применимым законодательством. Удаление аккаунта и связанных сообщений выполняется в пределах технических возможностей сервиса и обязательных сроков хранения.

6. Безопасность

Мы рекомендуем использовать уникальный пароль и не передавать его другим людям. Оператор должен применять актуальные меры защиты доступа, безопасную передачу данных, ограничение прав и регулярную проверку правил доступа. Ни один способ передачи или хранения данных не может гарантировать абсолютную безопасность.

7. Дети

QUN Messenger не предназначен для детей, если это прямо не разрешено условиями сервиса и применимым законодательством. Если оператор узнает, что данные были предоставлены с нарушением применимых возрастных требований, он должен рассмотреть вопрос об их удалении.

8. Изменения политики

Политика может обновляться при изменении функциональности, инфраструктуры или применимых требований. Актуальная редакция публикуется на этой странице с указанием даты обновления.

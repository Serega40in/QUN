## Приоритеты разработки

### P0 — доверие и работоспособность
1. Подключить русскоязычную базу знаний к runtime QUN AI.
2. Проверить функцию qun-ai-chat после развёртывания.
3. Добавить тесты ответов: ссылки, статусы, Market, Wallet, Coin, MAP, Guardian.
4. Проверить резервное копирование и восстановление действующих сервисов до миграции.

### P1 — QUN Node 0.1
- локальная конфигурация узла;
- health/status endpoint;
- ограничение ресурсов;
- синтетические тестовые данные;
- журнал событий без секретов;
- тесты отказа и перезапуска.

### P1 — QUN Storage 0.1
- локальное хранилище тестовых объектов;
- SHA-256 для каждого объекта;
- манифест содержимого;
- обнаружение порчи;
- создание и проверка реплики;
- тест восстановления при отключении узла.

### P2 — несколько независимых узлов
Регистрация узлов и статусов, минимум две независимые реплики, имитация отключения/повреждения, проверка автоматического восстановления, метрики времени восстановления и доступности.

### P3 — распределённые вычисления
После доказанного storage MVP: изолированные задачи, allow-list, квоты, sandbox и проверка результатов. Не исполнять произвольный пользовательский код на узлах.

## Правило обновления
Для каждого изменения указывать дату, коммит/релиз, ссылку, тест и статус (работает / прототип / план / пауза / не подтверждено). Не повышать статус без проверяемого доказательства.

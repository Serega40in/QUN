# QUN Stickers — руководство по созданию и публикации

**Версия:** 0.1 · **Первый набор:** Omnii — добро рядом · **ID:** qun_omnii_01

Это единый стартовый документ для авторов, художников и ИИ, которые будут создавать оригинальные стикеры QUN.

## 1. Идея первого набора

Начинаем с 24 статичных стикеров с Omnii — пушистым круглым персонажем с большими светло-голубыми кристальными глазами. Он добрый, живой, немного смешной и легко узнаваемый в маленьком размере.

**Паспорт персонажа**
- Почти круглое мягкое тело, слегка пушистый силуэт, короткие лапки.
- Молочно-белая/кремовая шерсть; большие выразительные светло-голубые глаза с кристальными бликами.
- Простая маленькая мордочка, без сложной анатомии.
- Акценты QUN: синий, изумрудный, мягкое золото — умеренно.
- Одинаковые форма глаз, пропорции и текстура на каждом изображении.
- Не использовать чужих героев, логотипы, водяные знаки, узнаваемые элементы чужих франшиз.

**Визуальное правило:** один персонаж на одном файле, без текста и коллажей. Вся фигура помещается в квадрат с запасом от краёв. Эмоция должна читаться при уменьшении до 128×128 px. Предпочтителен прозрачный фон. Если модель его не умеет — однородный фон #FF00FF без пурпурных деталей на персонаже, который затем удаляется отдельным этапом. Финальный стикер получает аккуратную белую обводку и мягкую тёмно-синюю тень.

## 2. Технический стандарт

Для QUN храним исходник и оптимизированную копию. Для Telegram готовим статичные PNG или WebP с прозрачностью.

| Параметр | Правило |
|---|---|
| Формат мастера | PNG с alpha |
| Формат публикации | WebP или PNG с прозрачностью |
| Размер для Telegram | одна сторона ровно 512 px, вторая не больше 512 px |
| Максимальный размер файла | 512 КБ для статичного стикера |
| Количество в первом наборе | 24 |
| Emoji | один или несколько подходящих emoji для каждого стикера |
| Отступ | персонаж не касается краёв |
| Имена | 01-hello.webp, 02-happy.webp и т. д. |

Требования Telegram: https://core.telegram.org/stickers и https://core.telegram.org/import-stickers. Перед публикацией проверяйте актуальные ограничения на официальной странице.

**Чек-лист приёмки**
- [ ] Это оригинальный Omnii, совпадающий с утверждённым эталоном.
- [ ] Эмоция понятна без подписи.
- [ ] Нет лишних/сломанных лап, артефактов, мусорных деталей.
- [ ] Персонаж целиком внутри кадра.
- [ ] Фон реально прозрачный, а не белая/клетчатая имитация.
- [ ] Стикер читается на светлой и тёмной теме.
- [ ] Размеры и вес соответствуют Telegram.
- [ ] Указаны emoji и сведения об авторских правах.

## 4. Какая ИИ подойдёт

**Основной бесплатный путь для первой серии: ComfyUI + Stable Diffusion 1.5 в бесплатной GPU-среде**, например Kaggle Notebooks, если в аккаунте доступна GPU-сессия. Это компромисс между качеством, стоимостью и доступностью. Бесплатные GPU-сессии имеют квоты, очереди и меняющуюся доступность — это не постоянный бесплатный сервер. Начинайте с теста из 3–4 изображений. Официально: https://www.kaggle.com/docs/notebooks

Модель SD 1.5 компактнее многих новых моделей и широко поддерживается. Перед коммерческим использованием прочитайте CreativeML OpenRAIL-M и карточку модели: https://huggingface.co/stable-diffusion-v1-5/stable-diffusion-v1-5. Лицензия содержит условия и ограничения; не считайте генерацию автоматически свободной от правовых вопросов.

**Для компьютера с 8 ГБ ОЗУ и Intel HD Graphics 505:** локальный ComfyUI в CPU-режиме может быть крайне медленным. Он пригоден для проверки запуска, но не рекомендован для массовой отрисовки. Документация ComfyUI: https://docs.comfy.org/development/comfyui-server/arguments. Не запускайте тяжёлую установку, пока не проверили свободное место.

Не советую начинать с FLUX или Z-Image на этом компьютере: модели тяжелее и потребуют подходящего GPU. Сначала докажем стабильность персонажа на небольшой тестовой серии.

## 5. Как генерировать, чтобы персонаж не менялся

1. Сначала сгенерировать четыре варианта нейтрального Omnii: стоит, смотрит прямо, мягко улыбается, без реквизита.
2. Выбрать один эталон и сохранить как omnii-reference.png.
3. Для каждого следующего стикера использовать один и тот же эталон через image reference / IP-Adapter, если workflow это поддерживает.
4. Не менять модель, стиль, ключевое описание персонажа и базовые параметры между изображениями.
5. Сначала сгенерировать по 3–4 варианта сюжетов 01, 06 и 09. Если персонаж меняется — исправить workflow до выпуска всей серии.
6. После одобрения сделать по 3 варианта остальных сюжетов; выбрать лучший.
7. Удалить фон, добавить обводку и тень, экспортировать в WebP/PNG, проверить размеры и прозрачность.
8. Сохранить исходник и финальную версию каждого стикера.

Не нужно обучать LoRA на случайных первых результатах. Сначала закрепите эталон и проверьте reference workflow. При необходимости можно отдельно подготовить набор одобренных изображений для обучения.

## 6. QUN Sticker Studio — локальное управление

Папка: [tools/qun-sticker-studio](../../tools/qun-sticker-studio/README.md).

- Установить Python 3.10+.
- Запустить start_windows.bat двойным щелчком.
- Браузер откроет http://127.0.0.1:8791.
- В студии можно импортировать PNG/WebP, вести библиотеку, отправлять промты в ComfyUI, отслеживать очередь и собрать ZIP с манифестом.
- Для генерации отдельно нужен ComfyUI и совместимая модель в backend/ComfyUI/models/checkpoints.
- Не включайте публичный доступ к локальному серверу. Он предназначен только для этого компьютера.

Опционально install_comfyui_cpu.bat установит ComfyUI и CPU-сборку PyTorch. Она скачивает несколько гигабайт, требует Python 3.12 и не скачивает модель. На данном ПК CPU-генерация будет медленной. После установки модели достаточно снова запустить start_windows.bat: он сам откроет ComfyUI и вкладку студии. Не запускайте установку, если не готовы выделить место и время.

Версия 0.1 — рабочая основа для подготовки и очереди генерации, не полноценный редактор. Маскирование фона, ручная ретушь и продвинутый референсный workflow будут развиваться отдельно. Ничего автоматически не загружается в облако и не публикуется.

## 7. Интерфейс художника и права

Стартовая форма: [QUN Sticker Artist Portal](./index.html). Автор выбирает изображения, просматривает их, указывает название набора, имя/псевдоним, инструменты и лицензию, подтверждает права и скачивает ZIP. Файлы остаются в его браузере и не отправляются на сервер автоматически. ZIP можно приложить к заявке GitHub по шаблону [sticker-submission](../../.github/ISSUE_TEMPLATE/sticker-submission.md).

**Права:** автор сохраняет авторские права. При отправке он отдельно предоставляет QUN неисключительное разрешение проверять, хранить, показывать и распространять принятый набор внутри сервисов QUN и в согласованных промоматериалах. Отправка не гарантирует принятие или публикацию. Условия нужно проверить с юристом перед открытым запуском.

Для AI-работ автор указывает сервис, модель и применимую лицензию. Нельзя отправлять чужих персонажей, логотипы, фотографии без прав, материалы с неизвестной лицензией.

Следующий этап — полноценный кабинет художника с QUN ID, приватной загрузкой в Supabase Storage, проверкой MIME/размера на сервере, RLS, модерацией и статусами: «черновик → отправлен → проверка → принят/отклонён → опубликован». Сейчас публичная загрузка на сервер намеренно не включена.

## 8. Публикация

**QUN Messenger:** пакет должен содержать превью, manifest.json (название, ID, автор, версия, лицензия, список файлов и emoji) и отдельные прозрачные WebP. Прежде чем включить набор в публичный каталог, проверяются авторство и качество.

**Telegram:**
1. Проверить прозрачность, размер и вес каждого файла.
2. Открыть официальный бот https://t.me/stickers.
3. Создать статичный набор, загрузить по одному файлу и назначить emoji.
4. Указать название и короткое имя.
5. Проверить ссылку вида https://t.me/addstickers/short_name.
6. Внести ссылку в карточку пака QUN после согласования с автором.

Telegram-публикацию совершает человек от своего аккаунта. Студия ничего не публикует без отдельного решения.

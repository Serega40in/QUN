QUN Core — собственный блокчейн, который мы строим шаг за шагом: от проверяемой локальной цепочки к независимым узлам и распределённому консенсусу. Прозрачно по устройству. Просто во взаимодействии.

Локальная разработка · не публичная сеть

Квинтэссенция QUN
Проверять — проще, чем слепо доверять. Сотрудничать — не значит терять свободу.

Интерфейс должен показывать главное сразу и открывать технические детали по запросу. Протокол должен позволять независимо проверять правила, подписи и историю, не обещая того, чего код ещё не умеет.

Основа протокола

Что уже есть и что строим дальше

Отделяем реализованные возможности от будущих этапов — без имитации готовой децентрализации.

01 · СЕЙЧАС

Проверка цепочки

SHA-256 хеши блоков, связи с предыдущим блоком, порядок блоков и обнаружение изменений в сохранённой истории.

02 · СЕЙЧАС

Подписанные переводы

Ed25519-подписи транзакций, проверка соответствия отправителя публичному ключу и тестовый локальный реестр балансов.

03 · СЛЕДУЮЩЕЕ

Проверяемый интерфейс

Обозреватель блоков, понятные статусы, просмотр транзакций и полный тестовый цикл с перезапуском узла.

04 · ПОЗЖЕ

Распределённая сеть

P2P-связь, независимые узлы, правила консенсуса и защита от конфликтующих историй. Это ещё предстоит реализовать и испытать.

Попробовать самому

Запусти QUN Core локально

Для разработчиков и тестировщиков. Нужен установленный Rust toolchain.

git clone https://github.com/Serega40in/QUN.git
cd QUN
git checkout codex/qun-core-node-api
cd core
cargo test
cargo run --bin node
Открыть локальный интерфейс ↗

Ссылка работает только на устройстве, где запущен узел по адресу 127.0.0.1:8787.

Перед тестированием

  • Это локальная экспериментальная сеть, а не mainnet.
  • Для тестового пополнения запусти узел с QUN_ENABLE_DEV_FUNDING=true.
  • Браузерный тестовый ключ хранится только в памяти вкладки и теряется после перезагрузки.
  • Не используй реальные средства и не открывай API в публичный интернет.
  • Консенсус, P2P и production-уровень безопасности ещё не реализованы.

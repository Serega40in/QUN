# QUN Core

**QUN Core — собственный протокол и код узла блокчейна QUN.** Это отдельный проект, а не токен, выпущенный в TON или другой существующей сети.

## Текущий статус

QUN Core находится на этапе **локального прототипа одного узла**. В Rust реализованы цепочка блоков, Ed25519-подписи, проверка nonce и балансов, HTTP API, сохранение снимка состояния и тесты восстановления. Локальный Explorer позволяет экспериментировать с узлом.

Это ещё не распределённая сеть: P2P, консенсус, синхронизация нескольких узлов, mempool и каноническое восстановление ledger из истории не реализованы. Не храните здесь реальные средства и не выставляйте API в интернет.

## Спецификация текущего прототипа

- [QUN Core protocol v0](../docs/core/protocol-v0.md) — текущие форматы и API, известные ограничения и обязательные условия перед devnet.
- Источник реализации и тестов: `core/src/lib.rs`, `core/src/bin/node.rs`, `core/tests/`.

Документ фиксирует текущее поведение, а не утверждает финальный wire-протокол. До независимого подключения узлов потребуется версия протокола с точной канонической сериализацией и тест-векторами.

## Инженерная дорожная карта

1. **Локальный узел — текущая база:** подписанные транзакции, валидация блоков, HTTP API, сохранение и тесты.
2. **Закрепить протокол:** каноническая сериализация, тест-векторы, правила genesis/эмиссии и детерминированное восстановление состояния.
3. **Сетевой слой:** P2P, идентификация и проверка сообщений узлов, ограничение ресурсов и синхронизация.
4. **Консенсус:** модель угроз, выбор канонической цепочки, финальность и защита от двойной траты.
5. **Devnet:** несколько независимых узлов, сетевые/property/fuzz-тесты, метрики и эксплуатационные инструкции.
6. **Testnet:** публичная спецификация, независимый аудит и отдельное решение о запуске.
7. **Mainnet:** только после аудита и подтверждённой устойчивой работы testnet.

## Локальный запуск

Нужен установленный Rust toolchain:

```sh
cd core
cargo test
cargo run
```

Запустить HTTP-узел:

```sh
cd core
cargo run --bin node
```

По умолчанию API слушает `127.0.0.1:8787`. Для тестового пополнения в локальной среде можно явно установить `QUN_ENABLE_DEV_FUNDING=true`; это вспомогательный механизм разработки, а не реальная эмиссия.

## Основные API-методы

- `GET /health` — статус локального процесса.
- `GET /chain` — цепочка.
- `GET /blocks/:index` — отдельный блок.
- `GET /accounts` — состояние локального ledger.
- `POST /dev/mine-signed` — проверка подписанных тестовых транзакций и создание блока.
- `POST /dev/fund` — тестовое пополнение, выключено по умолчанию.
- `POST /dev/mine` — legacy-демо-путь без криптографической аутентификации отправителя.

API не имеет аутентификации; оставляйте его на localhost.

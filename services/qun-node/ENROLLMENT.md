# QUN Node — безопасное подключение участников

**Статус:** публичное подключение и начисление QUN не реализованы. Добавлены локальные установочные сценарии для Windows и Android/Termux; они запускают тестовый узел на устройстве, но не регистрируют его в публичной сети.

Публичная страница: https://serega40in.github.io/QUN/node/  
Инструкция по запуску: [scripts/README.md](./scripts/README.md)

## Почему кнопка в браузере не может сама установить ноду

Обычная веб-страница не имеет права незаметно установить приложение, создать системную службу или постоянно работать в фоне. Это намеренная защита операционной системы. Корректный поток: пользователь выбирает устройство → скачивает подписанный установщик из официального источника → проверяет издателя и разрешения → явно подтверждает установку → управляет узлом из приложения/веб-панели.

На телефонах ограничения отличаются:
- **Android:** в будущем возможен отдельный проверяемый клиент/служба с явным согласием пользователя и уведомлением о фоновой работе. Нужны тесты энергопотребления, мобильной сети и политики распространения.
- **iOS/iPadOS:** нельзя обещать постоянно работающую storage-ноду; фоновые задачи сильно ограничены. Первым мобильным вариантом разумнее сделать мониторинг/управление, а не хранение и постоянную репликацию.

## Целевая архитектура присоединения

1. **Публичный сайт** — объясняет проект, проверяет совместимость, показывает требования и ведёт к подписанному релизу. Сайт сам по себе не получает доступ к диску и не регистрирует ноду.
2. **Node Agent** — локальный процесс с минимальными правами, ограниченным каталогом данных, лимитами диска/трафика/CPU и командой остановки. По умолчанию не открывает входящий порт в интернет.
3. **Регистрация узла** — пользователь инициирует присоединение, получает одноразовый короткоживущий токен, клиент создаёт собственную пару ключей, а сервер привязывает публичный ключ к регистрации. Нельзя встраивать общий секрет сети в клиент или делить один токен между всеми узлами.
4. **Канал управления** — исходящее TLS-соединение, проверка идентичности сервера, heartbeat, отзыв регистрации, обновления с проверкой подписи и ограничением скорости.
5. **Данные и репликация** — отдельный протокол QUN Storage: манифесты, хеши, проверка копий, repair, лимиты, шифрование в покое и при передаче, защита от replay и конфликтов. Текущий общий Bearer token годится только для доверенных локальных тестов.
6. **Измерение вклада** — журнал проверяемых задач, подтверждение результата и аудит до любых выплат. Сам факт, что клиент онлайн или хранит байты, не должен автоматически давать право на вознаграждение.
7. **Управление владельца** — состояние, использование ресурсов, журнал событий, pause/resume, безопасное удаление данных и полное удаление клиента.

## План реализации

### Этап A — устойчивый локальный прототип
- Автотесты на отключение/возврат узла, повреждённые данные/манифесты, конфликты и перезапуск процесса.
- Повторяемые результаты CI; fault-injection тесты и тест нескольких peers.
- Защита от бесконечных/слишком частых повторов, лимиты сетевых запросов, таймауты и наблюдаемость.
- Чёткое разделение локального API и доверенного межузлового API.

### Этап B — управляемая тестовая сеть
- Уникальные ключи узлов и одноразовое присоединение.
- Отзыв узла, allowlist тестовой сети, безопасный heartbeat.
- Без реальных пользовательских данных и без токенов вознаграждений.
- Тестирование восстановления после потери узла и проверки реплик.

### Этап C — установщики
- Подписанные сборки для Windows, macOS и Linux; контрольные суммы и инструкции проверки подписи.
- Обновление только подписанных версий с возможностью отката.
- Локальный интерфейс и uninstall/cleanup.
- Android — после отдельного прототипа и тестирования фоновых ограничений.

### Этап D — публичная сеть и экономика
- Threat model, независимый аудит, лимиты злоупотреблений и защита от Sybil.
- Прозрачные правила хранения, приватности, трафика и вознаграждений.
- Механизм QUN rewards — только после измеряемого полезного вклада, защиты от подделки отчётов и определения источника выплат.

## Текущая граница

Текущий QUN Node 0.1 — локальный тестовый прототип с вручную настроенными peers и общим секретом. Не запускать на публичных IP, не использовать для личных данных, не обещать выплаты и не считать публичную страницу работающим установщиком. Кнопки выбора устройства на странице пока показывают безопасный статус и команды локального теста, а не выполняют установку.
